# Plan 07 — Pin the wire formats and the decrypt-failure semantics

**Kind:** test hardening (security-critical) — test-only, no production change expected
**Status:** proposed
**Depends on:** nothing

---

## Problem

`pkg/crypto` and `pkg/processor` sit at 85% and 94% line coverage, and the suite does not
protect the two properties the project cares most about:

1. **The wire formats are frozen** (`AGENTS.md`; ADR 0001 constraint 1; `docs/plans/README.md`
   "Conventions"). No test holds a ciphertext produced by an *earlier* build. Every test
   encrypts with today's encoder and decrypts with today's decoder, so a change that moves
   both sides together round-trips perfectly and strands every file ever committed.
2. **A marker that fails to decrypt is an error, never a value.** Three separate places
   enforce that, and no test reaches any of them in the shape production uses.

### Evidence

Each row is a single change applied to a scratch copy of the repo, with `go test ./...` run
across the whole module. Every one leaves the suite green.

| # | Mutation | Consequence if shipped | Verified |
|---|----------|------------------------|----------|
| M1 | `pkg/crypto/crypto.go:37-38` and `:57-58` — swap the ephemeral-pubkey and nonce offsets on both encrypt and decrypt | every existing `v1:` marker becomes undecryptable | re-verified |
| M2 | `pkg/processor/processor.go:191` — `if !ok {` → `if !ok && false {` after `secretbox.Open` | a flipped byte in a v2 payload "decrypts" to an empty value; `run` exports `FOO=` with exit 0 | re-verified |
| M3 | `pkg/processor/processor.go:225` — `if errors.Is(err, ErrSkip) {` → `if err != nil {` in `CompositeDecryptor` | wrong key / corrupt ciphertext in any project with both key types is downgraded to *skip*; `decrypt` and `run` hand ciphertext downstream as the value, exit 0 | re-verified |
| M4 | `processor.go:266` — delete `lastErr = err` in `EncryptContent` | a failed encrypt (e.g. a KMS `Wrap` error) leaves plaintext in the file, exit 0 | audit |
| M5 | `pkg/crypto/crypto.go:51` — length guard → `if false {` | inputs under 56 bytes panic at `data[56:]` inside `decrypt`/`run` | audit |
| M6 | `processor.go:62` — drop `v2WrappedSize` from the truncation minimum | `StructureCheck` accepts truncated v2 markers | audit |
| M7 | `processor.go:313` — delete the `continue` after a hard decrypt error | the failed marker is replaced by an empty string in the output | audit |
| M8 | `pkg/processor/marker.go:201` — `opensMarkerAt` check → `if false` | a ciphertext body can swallow a second marker on the same line (ADR 0001 says this case exists) | audit |
| M9 | `marker.go:173` — `i > 1` → `i >= 1` | `isCiphertextStart` disagrees with `IsEncryptedInner` on `v:`; `ENC[v:secret]` is treated as ciphertext and never encrypted | audit |
| M10 | `marker.go:376` — remove `i == 0 &&` from the `\v` offset-0 rule | escape semantics drift with no failing test | audit |

"re-verified" = reproduced independently in the main session; "audit" = applied by the
audit agent against its own scratch copy.

v2 is only partly protected today, and by accident: `pkg/processor/rewrap.go:68-90` parses
the envelope layout a second time, independently, so a matched v2 layout change trips
`TestRewrapContent*` and `TestKmsRotateRewrapsFileAndUpdatesPubkey`. If `rewrap.go` is ever
refactored to share the parser, that protection disappears.

---

## Goals

1. A committed **golden vector** for each wire format that must decrypt forever.
2. Every way a marker can fail to decrypt — wrong key, tampered payload, truncation — is
   asserted as an error, through the **same decryptor composition production builds**.
3. The scanner's documented edge cases each have a test that fails under the matching
   mutation above.

### Non-goals

- Changing any byte of either format. If writing a test reveals a real defect, stop and
  write it up separately; this plan is test-only.
- Property-based / fuzz testing. Worth doing (see "Follow-ups"), but golden vectors and
  targeted cases close the verified holes first.

---

## Design

### Golden vectors — `pkg/processor/testdata/`

Generate them **from a released build**, not from the current tree, so the vector is
evidence of compatibility rather than a restatement of today's code. `v0.0.7` already emits
both formats.

```
pkg/processor/testdata/
  golden_v1.key        # fixed NaCl private key (base64, as keygen writes it)
  golden_v2_rsa.pem    # fixed RSA-2048 private key — test-only, never a real key
  golden.env           # one v1 marker, one v2 marker, known plaintexts, generated by v0.0.7
  README.md            # how these were produced, and "never regenerate"
```

Use a throwaway `main` in a scratch module that requires
`github.com/rubysolo/envisible v0.0.7` and calls its encryptors **directly**, not the CLI:
v0.0.7 predates the plan 01 marker scanner, so its CLI cannot express a plaintext containing
`]` or a newline. Calling the encryptors sidesteps the marker grammar entirely; the bytes that
matter (the ciphertext) are the same either way.

- v1: `crypto.Encrypt(plaintext, pub)` from v0.0.7 with the fixed keypair, wrapped as
  `ENC[v1:...]`.
- v2: v0.0.7's `EnvelopeEncryptor` with an `RSAWrapper` over `golden_v2_rsa.pem`'s public
  half, wrapped as `ENC[...]`.
- Record the generator's source in `testdata/README.md`; do not commit it as code.
- Choose plaintexts that exercise more than ASCII: one with a NUL, a multi-byte UTF-8
  sequence, a newline and a `]`. The ciphertext encodes any bytes, and decrypting them
  through today's `DecryptContent` then exercises today's output escaping on the way out.

The test decrypts `golden.env` through `CompositeDecryptor{NaclDecryptor, EnvelopeDecryptor}`
— the composition `cmd/keys.go` builds for mixed files — with the envelope side backed by an
unwrapper over the fixed RSA key, and asserts the exact plaintexts. It also runs `Scan` on
the same bytes and asserts each marker's `Start`/`End`/`Encrypted`, so the marker grammar is
pinned along with the cryptography.

Add one line to the `testdata/README.md` header and to `AGENTS.md` "Conventions": *a failing
golden-vector test means the wire format changed; fix the code, never the vector.*

### Tamper and wrong-key matrix

One table-driven test per format, each case asserting **both** `DecryptMarker` returns a
non-`ErrSkip` error **and** `DecryptContent` returns an error with the marker left intact in
its output (that second assertion is what catches M7):

| case | v1 | v2 |
|------|----|----|
| wrong key | ✓ (exists, via bare `NaclDecryptor`; move to composite) | ✓ |
| one byte flipped in the payload | new (`crypto_test.go`) | new — flip a byte after `wrappedSize+24` (M2) |
| one byte flipped in the wrapped key | n/a | new |
| truncated, valid base64 (`v1:AAAA`, `v2:` + 40 bytes) | new — must error, must not panic (M5) | new (M6) |

Run every case through `CompositeDecryptor`, not a bare decryptor. That alone closes M3.
Add one direct `CompositeDecryptor` test: a v1 marker sealed to a *different* key, asserting
the error is non-nil and not `ErrSkip`.

### Encrypt-side failure

A stub `Encryptor` whose `EncryptValue` returns an error. Assert `EncryptContent` returns it,
and that the output is not a partially-encrypted file the caller might write (M4).

### Scanner edge cases (`marker_test.go`)

- Same-line swallow: `a: ENC[v1:AAA b: ENC[v1:BBB=]` → a `MalformedCiphertext` defect for the
  first token **and** the second marker recognized (M8).
- Prefix agreement: a table over `v:`, `v1`, `v1:`, `v12:`, `vx:`, `V1:` asserting
  `isCiphertextStart` and `IsEncryptedInner` return the same answer (M9).
- `\v` only at offset 0: `ENC[\vsecret]` vs `ENC[a\vb]` (M10).

### Tighten existing weak assertions

- `TestStructureCheck` (`processor_test.go:439`): its `v2_truncated` case is
  `v2Inner[:10]+"=="`, which is invalid base64 and fails at decode, never reaching the length
  check. Use valid base64 of a too-short blob, and assert on the error text (`truncated`) in
  every case.
- `TestDecryptErrors` and the `RewrapContent` error tests: also assert the returned content.
- No test anywhere asserts that decrypt errors exclude plaintext. Add one: decrypt a v2
  marker with a wrong unwrapper and a v1 marker with a wrong key, and assert the known
  plaintext is not a substring of `err.Error()`.

## Implementation

1. Generate and commit `testdata/` from `v0.0.7` (above); write `testdata/README.md`.
2. `pkg/processor/golden_test.go` — golden decrypt + `Scan` assertions.
3. `pkg/crypto/crypto_test.go` — v1 tamper and truncation cases.
4. `pkg/processor/processor_test.go` — the composite tamper/wrong-key matrix, the composite
   hard-error test, the failing-`Encryptor` test, and the tightened `TestStructureCheck` /
   `TestDecryptErrors`.
5. `pkg/processor/marker_test.go` — the three scanner cases.
6. `AGENTS.md` — one line under Conventions pointing at the golden vectors.

## Follow-ups

- `go test -fuzz` targets for `Scan` (no panic; `Start <= End`; markers never overlap) and for
  round-trip fidelity over arbitrary bytes. These would have found M8 without a human
  thinking of the case.
- When the next release ships, add its vectors next to `v0.0.7`'s rather than replacing them.
